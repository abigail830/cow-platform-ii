# Documents

Document channels (folder tree), per-channel pipelines and metadata extraction, and the PaddleOCR-VL parsing pipeline driven by **`openkms-cli`**.

For **lifecycle maintenance without pipeline** (channels, upload, status, versions, metadata, policy lifecycle, relationships, schema): see [document-lifecycle-basics.md](document-lifecycle-basics.md).

## Document parsing (PaddleOCR-VL and Baidu Cloud)

- **PaddleOCR-VL (Baidu Cloud API)** — `paddleocr-doc-parse` is a **deprecated alias** of `baidu-doc-parse` (same paddle-vl-parser API, no local `paddleocr` install). **Platform async** via `pipeline run-async`. Office/XLSX formats use **Adobe PDF Services** before upload when needed (`OPENKMS_ADOBE_*` in `openkms-cli/.env`).
- **Baidu Cloud PaddleOCR-VL API** (`baidu-doc-parse` pipeline) — **platform async**: `pipeline run-async` (submit → poll → finalize in one CLI worker). Uploads to **private Baidu BOS**, submits **presigned `file_url`** to paddle-vl-parser; credentials **`OPENKMS_BAIDU_CLOUD_*`**, bucket **`OPENKMS_BAIDU_BOS_BUCKET`**
- Supports: PDF, PNG, JPG, JPEG, WEBP (paddle + baidu + aliyun); **DOC/DOCX/PPT/PPTX/XLS/XLSX/TXT/RTF** on paddle via **Adobe**; **DOCX/PPTX/XLS/XLSX** and more on baidu (XLS/XLSX via **Adobe→PDF** before cloud API); **EPUB** on baidu only (CLI converts with **mutool** before upload when needed); **XLSX** on aliyun via DocMind native; **MD/MARKDOWN** on all pipelines via shared **markdown-ingest** (no VLM/cloud parse)
- Output: Markdown, layout detection, parsing result JSON
- Configurable: server URL, model, max concurrency
- **Channel metadata extraction** during pipeline: if the extraction LLM errors (e.g. HTTP 502), the CLI logs a warning and **still completes** the parse so the document can reach `completed`; use **Extract** on the document page when the model is healthy. Extracted fields are written to **`{file_hash}/extracted_metadata.json`** on storage; the worker merges them into the document row when the job finishes. Before LLM extraction, **openkms-cli** calls **`GET /internal-api/documents/{id}/metadata-needs-extraction`**; skips extraction when channel schema fields already have values. On re-process with cached parse output, metadata extraction runs only when that check reports empty fields (both **paddleocr-doc-parse** and **baidu-doc-parse**).

## openkms-cli

- **CLI** at `openkms-cli/` built with Typer (≥0.9.0)
- **Tests:** `openkms-cli/tests/` — `pip install -e ".[dev]" && pytest tests/` (no local paddleocr required)
- **Configuration**: `openkms_cli/settings.py` (`CliSettings`, pydantic-settings) lists every supported env var via `validation_alias`; parse/pipeline/auth read through `get_cli_settings()`; Typer no longer duplicates env via `envvar=`
- **Parse**: `openkms-cli parse run <input> [--method baidu-doc-parse]` — Baidu Cloud paddle-vl-parser API (`paddleocr-doc-parse` is a deprecated alias)
- **Pipeline**: `openkms-cli pipeline run-async --job-id {job_id}` for Baidu / Aliyun async jobs (submit → poll → finalize in one CLI worker)
- **Metadata extraction**: when channel has `metadata_extraction_model_id`, the worker resolves the model via `GET /internal-api/models/cli-params` and passes `--extract-metadata` with `--extraction-model-base-url`, `--extraction-model-name`, and `--extraction-api-key`; CLI does not call backend for model config on platform runs. Manual CLI may pass only `--extraction-model-name` to resolve via the same `cli-params` endpoint. Extracts via pydantic-ai **PromptedOutput(StructuredDict)** with `response_format: json_object` (DeepSeek-compatible), PUTs to **`PUT /internal-api/documents/{id}/metadata`** (system path; no channel write ACL); **LLM failure does not fail the pipeline** after a successful parse
- Install: `pip install openkms-cli[pipeline,baidu,aliyun,metadata]` — **no local paddleocr / mlx-vlm-server**
- Output structure on storage: `documents/{file_hash}/original.{ext}`, `result.json`, `markdown.md`, `page_index.json` (when pageindex installed), `layout_det_*`, `block_*`, `markdown_out/*` (logical paths in `result.json` may still use `{file_hash}/…`; API resolves to the new prefix)
- **Backend integration**: subprocess-invokable for async jobs
- **Extensible**: developers can add new Typer subapps in app.py
